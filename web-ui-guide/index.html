Overview

Section titled “Overview”

The LMA web UI is a React application hosted on Amazon S3 and served via Amazon CloudFront. Authentication is handled by Amazon Cognito, which manages user sign-up, sign-in, and access control. The UI provides real-time meeting transcription, an AI-powered chat assistant, meeting management, and administrative configuration.

Navigation

Section titled “Navigation”

The left sidebar organizes the application into the following sections:

Sources

Section titled “Sources”
  • Virtual Participant — Join meetings via a virtual participant bot
  • Stream Audio (from Mic+Browser) — Stream audio directly to LMA from any Chrome tab (meetings, softphones, YouTube, audio/video playback)
  • Chrome Extension — Information, download, and install instructions for the LMA Chrome browser extension (see Browser Extension)

Meetings

Section titled “Meetings”
  • Meeting List — View and manage all accessible meetings
  • Meetings Query Tool — Advanced search and filtering across meetings

Troubleshooting (admin only)

Section titled “Troubleshooting (admin only)”
  • Troubleshooting — Ask the AI troubleshooting agent why something in the deployment failed; it reads the deployment’s logs, Virtual Participant records and stack parameters and answers with a root cause and its evidence (see AI Troubleshooting Agent)

Configuration (admin only)

Section titled “Configuration (admin only)”
  • View / Edit Configuration — The configuration profiles, and every runtime setting of the one open in one place: summary prompts, chat buttons, Nova Sonic, transcription engine, meeting cost prices and more, with each profile’s saved revisions to view, compare, label and restore (see Configuration Guide)
  • MCP Servers — Install and manage MCP server integrations
  • User Management — Create and delete LMA users (see User Management)

Deployment Info

Section titled “Deployment Info”
  • Stack name, build date, and version information

Meeting List / Dashboard

Section titled “Meeting List / Dashboard”

The meeting list provides a searchable dashboard of all meetings you have access to.

  • Columns: Meeting Topic, Date/Time, Duration, Status, Owner, Shared With
  • Status indicators: In Progress, Ended
  • Multi-select: Check multiple meetings for batch operations (share, delete)
  • Configurable time range: Use the Load dropdown to choose a preset window (2 hrs, 4 hrs, 8 hrs, 1 day, 2 days, 1 week, 2 weeks, 30 days) or pick Custom… to open a modal with explicit Start date + Start time (UTC) + End date + End time (UTC) inputs (±365-day window). The selected range is persisted in localStorage and the list header shows both the number of loaded meetings and the RBAC-filtered server-side total (e.g. 42 loaded of 127 or 500+ when the count is truncated). The meeting list is served by a DynamoDB GSI (TypeDateIndex) and a Lambda resolver that paginates a single date-range query, so performance scales to thousands of meetings without scans.

Use the search bar to filter meetings by topic or other attributes.

Manual Action Alerts

Section titled “Manual Action Alerts”

A persistent Flashbar at the top of the LMA UI surfaces any of your Virtual Participants currently in the MANUAL_ACTION_REQUIRED state — a CAPTCHA, 2FA prompt, SSO redirect, unknown consent dialog, or other Zoom verification step that needs human input. Each alert links directly to the affected meeting detail page where you can open the live VNC viewer and complete the challenge.

  • Alerts arrive in real time via an AppSync GraphQL subscription, with a one-time backfill on page load so anything fired while the tab was closed still shows up.
  • Each alert is dismissible — dismissed alerts are remembered in localStorage (per VP id) so they don’t reappear on every refresh after you’ve dealt with them.
  • If you grant the browser notification permission in the LMA UI, you also get a desktop notification + audio chime when a new MANUAL_ACTION fires — useful when you’re tabbed-away or in another window. Most browsers prompt for this permission on first sign-in; deny and it falls back to in-page alerts only.

See Troubleshooting › VP Stuck at MANUAL_ACTION_REQUIRED for how to resolve specific challenge types.

Virtual Participant Pages

Section titled “Virtual Participant Pages”

The Virtual Participant section of the UI has two views.

Virtual Participant List

Section titled “Virtual Participant List”

The Virtual Participants sidebar entry opens a list of your in-flight and recent VPs, with status, owner, meeting platform, and meeting name. New VPs appear in the list without a page refresh — the list subscribes to onCreateVirtualParticipant GraphQL events. Those events, like the list itself, show a VP to its owner, the users it is shared with, and Admins.

Create Virtual Participant modal

Section titled “Create Virtual Participant modal”

The Create Virtual Participant button opens a modal where you enter meeting details and launch the VP. When Zoom is selected as the platform, the modal includes a Zoom account card:

  • ✅ Signed in as user@example.com — [Update] [Remove] — your stored Zoom credentials are present. Tick “Sign in with my stored Zoom account when joining this meeting” to use them; the VP signs in to Zoom before navigating to the meeting URL.
  • ⚠ Not configured. The VP will join as a guest. [Add Zoom credentials] — no credentials stored. Click to open a sub-modal with username + password fields. Credentials are stored in AWS Secrets Manager scoped to your Cognito sub; the plaintext password is never returned to the UI.

For the full sign-in flow, join-reliability notes, and operational caveats, see Zoom Sign-in & Join Reliability.

The modal also has an optional Agenda field, one item per line. Paste Meeting Invitation fills it from the invitation when the invitation lists an agenda. The agenda is stored with the VP and placed on the meeting record when the meeting starts, for meetings started now and scheduled ones alike. See Meeting Agenda.

Virtual Participant detail page

Section titled “Virtual Participant detail page”

Click a VP from the list to open its detail page. The page shows:

  • Connection details — platform, meeting ID, duration, status (with the granular status lifecycle described in Virtual Participant › Status Lifecycle).
  • Action banner above the VNC viewer when the VP is in MANUAL_ACTION_REQUIRED — describes what challenge needs solving (CAPTCHA, 2FA, SSO, etc.).
  • Live Virtual Participant View — embedded noVNC viewer of the VP’s Chrome window. Toggle View Only off to interact with the VP’s browser (type a 2FA code, solve a CAPTCHA, click through SSO).
  • Troubleshooting card — when a VP fails, the human-readable errorMessage written by the VP backend is displayed here, along with common solutions for that error class.
  • Status history with timestamps for each state transition.
  • Diagnose in the page header — runs the AI troubleshooting agent’s diagnosis of this Virtual Participant: whether it joined, and if it failed or ended early, why. Shown to Admins only; see AI Troubleshooting Agent › The Diagnose button.

Meeting Detail Page

Section titled “Meeting Detail Page”

Clicking a meeting from the list opens the meeting detail page: a compact header with what the meeting was, and four tabs under it. The selected tab is part of the page’s address (#/calls/<Meeting ID>?tab=summary), so a link or a reload opens the same tab; a link without one opens the Transcript tab. A link saved when the Summary tab was called Overview (?tab=overview) still opens it. Switching tabs keeps each tab as it was, including a summary or agenda being edited and the transcript’s translation and scroll position. The meeting assistant is a panel beside the tabs, on every tab; see Meeting assistant panel.

Meeting header

Section titled “Meeting header”
  • Title — the meeting’s name, without the date and time its source added to the Meeting ID (for example Weekly sync for Weekly sync-2026-11-03-14-05-09-123). The full Meeting ID is in the title’s tooltip, the copy button beside it copies it, and the Details tab shows it. A Meeting ID without a recognised date and time is shown as it is.
  • Status, start time and duration — the start time is shown in your own time zone, with the stored UTC value in its tooltip. The duration is the longer of the meeting’s stored duration and the time the loaded transcript reaches (see Duration).
  • Platform — when a Virtual Participant joined the meeting, the platform it joined (Zoom, Microsoft Teams, Amazon Chime, Webex).
  • Consent — the consent setting that applied to the meeting and where it stands, such as Consent Opt-in · granted, or Consent enforcement off when consent was off (or never started) for it. Selecting it opens the consent record, or the consent setting, on the Details tab. While a meeting with consent in notify or opt-in mode is live and recording and transcription are withheld, a warning above the tabs says that transcription is paused until consent is recorded, or that a participant objected, once the meeting has run for 30 seconds (the time a notice normally takes to be posted and answered); Show the consent record opens the record.
  • Owner and Speakers — the people heard in the meeting, by the names the transcript shows for them: a name shown as one person is listed once however many voices it has, and a name shown as several people is listed once per voice (ConfRm_1 · Voice 1, or the name given to that voice). The list follows a renamed voice or a changed choice at once. Selecting a speaker opens that speaker’s voice in the Speakers panel on the Details tab, with its name field ready for typing; Name speakers opens the panel itself.
  • Est. cost — the meeting’s estimated cost. Select it to see the itemised estimate; see Meeting Cost Estimate.
  • Assistant — opens and closes the meeting assistant panel, when the deployment has the meeting assistant enabled. A dot on the button means an answer finished while the panel was closed.
  • Share, Download and the ⋮ menu — Download is the one place a meeting is taken away from. It offers the summary and, once the meeting has ended, the transcript, each as Markdown (.md), Word (.docx) and Plain text (.txt), the transcript also as Excel (.xlsx), and each can be copied to the clipboard as Markdown (Copy to clipboard (Markdown); the header confirms the copy). The summary can also be sent with Email summary (beta). See Transcript Downloads. Delete meeting is in the ⋮ menu. Share and Delete open the same dialogs as on the meeting list.
  • Diagnose — runs the AI troubleshooting agent’s diagnosis of this meeting: whether it was captured and transcribed from start to end, and if anything failed, why. Shown to Admins only; see AI Troubleshooting Agent › The Diagnose button.

Duration

Section titled “Duration”

The stored duration (TotalConversationDurationMillis) is written as transcript segments are processed. For meetings recorded with this version or later it is the latest end time of all the meeting’s final speech segments, and the meeting list, the summary download and the MCP tools read it. Meetings recorded with an earlier version keep the value they were stored with, which is the end time of whichever final segment was written last rather than the latest one, and can be shorter than the meeting.

So that those older meetings also read correctly, the page shows the longer of the stored value and the end of the last final transcript segment it has loaded; when the two differ, the Details tab gives the stored value as well. Both are measured on the transcript’s clock, from when transcription started, so a recording that began before transcription can be longer than either.

Summary tab

Section titled “Summary tab”
  • Meeting Summary — the summary from the configured prompt templates, with Regenerate and Edit; its downloads are in the header’s Download menu. Each section of the summary (SUMMARY, DETAILS, ACTIONS, SCREEN SHARE SUMMARY and so on, one per prompt template) opens and closes on its own. A line of links above them opens a section and moves to it, with Expand all and Collapse all beside it. SUMMARY starts open and the others closed; the sections you open or close are remembered in your browser, by section name, for every meeting. A summary edited by hand is split into sections at its headings (a Markdown heading, or a bold line in capitals such as **ACTIONS**).
  • Pictures of the shared screen — the key frames named in the SCREEN SHARE SUMMARY section (SLIDES PRESENTED in a summary written by a 0.4.0 pre-release) are shown as their thumbnails, read only once the section is opened. Selecting one opens the Screen share tab at that frame (or, for a meeting whose frames have not loaded on the strip, the full-size picture); a frame that can no longer be read shows as its caption. The CHAPTERS section is shown once, as the Chapters list beside the summary, and the AGENDA COVERAGE section under the agenda it describes. Downloads and copies of the summary still include every section. See Transcript Summarization.
  • Chapters — the meeting’s chapters; selecting one opens the Transcript tab at its time and, after the meeting, plays the recording from there in the player. See Meeting Video and Key Frames.
  • Agenda — the meeting’s agenda, who last changed it, and its coverage. A meeting without an agenda shows one line with Derive agenda and Add agenda for those who can change it. See Meeting Agenda.
  • Sentiment charts, when sentiment analysis is enabled; see Sentiment Analysis.

Transcript tab

Section titled “Transcript tab”

The tab a meeting opens on. Real-time transcription displayed with:

  • Speaker names and timestamps for each segment; select a name to rename that voice (see Naming the voices)
  • Sentiment indicators per segment
  • Color-coded entries by channel for easy visual distinction between speakers
  • Auto-scroll: while the meeting runs it keeps the newest segment in view; after the meeting, with a recording, it keeps the segment being played in view. Scrolling away pauses it, and Resume returns to the newest segment or to the one being played
  • Translate, with the language chosen beside it; see Live Translation
  • Search the transcript and the speaker filter; see Searching and filtering
  • Messages typed in the meeting chat, where a Virtual Participant added them; see Meeting chat messages

The transcript keeps its own scroll area, sized to the window, so following a live meeting keeps the newest segment in view while you can still scroll back.

The recording player

Section titled “The recording player”

Once a meeting has ended and its recording has been stored, a player sits above the transcript. It plays the video recording when the meeting has one (the video file carries the meeting’s audio as well) and otherwise the audio recording; a meeting with both has a Video / Audio only switch, which keeps the place. During a live meeting there is no player, because neither recording exists until the meeting ends. The player stays at the top of the window when the page is scrolled.

  • Controls — play/pause, the time, the seek bar, the speed (0.75x to 2x), mute and, for video, full screen. Each has an accessible name, and the seek bar is a slider that the keyboard moves.
  • Chapters on the seek bar — each of the meeting’s chapters is a mark on the seek bar, with its title shown on hover or focus; selecting a mark plays from that chapter. The chapter being played is named under the bar.
  • The transcript follows the recording — the segment being heard is highlighted, and kept in view while Auto-scroll is on. Scrolling the transcript while it plays stops it following (a notice says so, with Resume); playing from a segment, a chapter or the seek bar follows again.
  • Playing from a segment — after the meeting, each segment’s time is a link: selecting it plays the recording from the start of that segment. Only the time is a link, so the segment’s text can still be selected and copied and its speaker renamed.
  • Keyboard — with the Transcript tab open and the focus not in a text field, Space plays or pauses and Left / Right move 5 seconds. Space is left to a focused button or link, which it presses, and the arrows to a focused slider.
  • Only one thing plays — opening another tab pauses the player. The Details tab has no player of its own: its recordings have Play, which opens this tab and plays, and Open file.

From the other tabs, a time selected moves the player as well as the transcript:

SelectedTab shownPlayer
A chapter in the Overview’s Chapters listTranscriptplays from the chapter
A thumbnail on Screen sharestays on Screen sharemoves to the frame, paused

The ones that only move the player are for looking at something rather than listening to it; the player is then ready at that point when the Transcript tab is opened.

Lining the recording up with the transcript
Section titled “Lining the recording up with the transcript”

Transcript times are on the transcript’s clock, which starts when transcription of the meeting starts; a recording has its own, from the start of its file. The player converts between them:

SourceAudio recordingVideo recording
Virtual ParticipantStarts with transcription: the same clock. A pause (LMA pause) is kept in it as silence, because the transcript’s clock runs on through a pause tooStarts before the Virtual Participant is admitted, so it is ahead of the transcript by the time spent joining and in the lobby, and by more after each reconnection of its transcription (the video records through the gap; the transcript and the audio recording skip it). Lined up from the key frames, as below
Stream AudioStarts with transcription. When the page reconnects within the 60 seconds the transcriber holds a dropped meeting, the recording and the transcript continue together; audio the page could not send meanwhile is missing from both (the page buffers about the last 3 seconds of an outage and sends them after reconnecting)None
The browser extensionStarts with transcriptionNone
Desktop Capture AppStarts with transcription. When the app reconnects within the 60 seconds the transcriber holds a dropped meeting, the recording and the transcript continue together. Audio the app could not send meanwhile is missing from both (the app buffers about the last 3 seconds of an outage and sends them after reconnecting)Its file is built with the audio recording as its sound and the video placed against it, so it starts on the same clock. The app keeps recording video through a dropped connection and sends it after reconnecting, so after a reconnect the video, and the transcript times of its key frames, are ahead of the audio and the transcript by the audio that was lost. Key frames from a video stream the app restarted afresh are placed at the audio received so far, which is on the transcript’s clock
Upload AudioThe uploaded file itself, which is what was transcribedNone

Each key frame records both its time in the transcript and its place in the video recording, so the player lines the video up using the key frame nearest before each time; this follows a Virtual Participant’s video across its pauses as well. A Virtual Participant meeting whose video has no key frames therefore starts on the audio recording, which lines up with the transcript: the player says why, and so does the video recording on the Details tab. Video still plays the video, as if it started with transcription, which plays each point earlier in the meeting than the transcript line it was started from, by the time the Virtual Participant took to join. The choice is made once the key frames have loaded, so the player can change to the audio a moment after the page opens. The video of any other source has no such offset and plays without key frames. A video stored without sound (when a Virtual Participant’s audio was not ready as its recording started, or when the desktop app’s video could not be combined with the audio) plays silently, and Audio only plays the sound. With more than a hundred key frames, only the ones loaded so far (the first hundred, more as the Screen share strip is scrolled) are used. Small differences are expected where the transcription engine places a word a little early or late. A Desktop Capture App meeting whose connection dropped for longer than the transcriber holds it (60 seconds), or that reconnected to a different transcriber task, has a second transcript session that starts again from zero; see Reconnection.

Meeting chat messages

Section titled “Meeting chat messages”

When a Virtual Participant adds the meeting chat to the transcript (see Meeting Chat in the Transcript), each message is its own line among the speech, at the time the VP read it. It is set apart from what was said by a chat icon, a tinted background, and the label Alice · chat in place of a speaker’s name. Two messages in a row from one sender are never joined into one line, as two spoken segments can be.

A message is shown exactly as it was typed, line breaks included. Nothing in it is formatted: **bold** stays as typed, and HTML is shown as text. Each web address in it (one starting http://, https:// or www.) is shown as code with a copy button beside it, and is never a link the page follows; copy it and paste it where you choose. Other kinds of address, such as javascript: or data:, are left as plain text.

The sender is the name the meeting’s chat showed, or Unknown sender. Naming a voice does not rename a chat sender, and a chat sender is not offered as a speaker to name. Chat messages have no sentiment and are left out of the sentiment charts.

With a recording, a chat message’s time plays the recording from there, as a spoken line’s does. The highlight and the scrolling that follow the recording pass over chat messages, since they were typed rather than heard.

Searching and filtering

Section titled “Searching and filtering”
  • Search the transcript marks every segment that holds all the words typed, in any order, ignoring case and accents (the same rule as the search of the shared screen’s text), and highlights the words. The first match is shown at once; Enter or Next match moves to the next, Shift+Enter or Previous match to the previous, and the count shows which match is shown. Moving between matches while the recording plays stops the transcript following it, as scrolling does. Matches are marked rather than the other segments hidden, so each is read with what was said around it. The search reads the segments as transcribed, not their translations. Chat messages are searched too, and their matching words highlighted.
  • Speaker chips — All and one chip for each speaker, by the names shown in the transcript. Choosing speakers shows only their segments (and hides the assistant’s answers); choosing All shows everything again. The search works within the speakers chosen.
  • One person | Several people — the chips are grouped by the name the meeting platform showed, and a name that speaker separation heard several voices under has a small menu beside it, shown as a person icon (one person) or a group icon (several people); its tooltip says why the name is shown that way. One person shows every line under the name alone (Bob Strahan, not Bob Strahan (spk_0) and (spk_1)); Several people gives each voice a chip of its own — ConfRm_1 · Voice 1, Voice 2 — with a pencil to name that voice in place, which renames every line it spoke. The field opens empty, with ConfRm_1 · Voice 1 as its placeholder; Enter or moving away saves the name, Escape cancels, and clearing a name goes back to Voice N; More options opens the speaker’s dialog. The same menu is beside the name in the Speakers panel. LMA picks a default for each name — several people for a room or a room device, or when two voices each spoke at length, one person otherwise — so the menu is only needed where that guess is wrong; see One person or several people. The choice is saved with the meeting and applies to the downloads, the summary and the Meeting Assistant too. It can be changed by the same people who can name speakers.
  • Naming a speaker from its chip — for those who can name the meeting’s speakers (its owner, an Admin, and anyone it is shared with), the pencil beside a chip opens that speaker’s dialog: give the voice a name (which renames every segment it spoke, earlier ones included), say it is the Same person as another voice on its channel, or Separate a voice combined into it. When two voices are shown under one name, it can combine them into one person. It writes the same names as the Speakers panel on the Details tab, which remains the place to paste an attendee list, confirm or reject a suggested name, or lock a name.
  • Chat — shown when the transcript holds meeting chat messages. On by default; turning it off hides every chat message, and turning it on shows them again. It works on its own, whichever speakers are chosen: with a speaker chosen and Chat on, the transcript shows that speaker’s segments and all the chat.

During a live meeting with a Virtual Participant, the VP’s live view (a real-time VNC viewer of the VP’s browser) appears at the top of this tab when it is opened from the assistant panel’s settings menu (Open VP Live View) or by the assistant. Opening it from another tab switches to this one. You can see and control what the VP sees in the meeting.

Meeting assistant panel

Section titled “Meeting assistant panel”

The meeting assistant’s chat, in a panel on the right of the page, available on every tab. Assistant in the header opens and closes it, and the panel’s ✕ closes it too, as does Escape while the keyboard focus is in the panel. Opening it puts the focus in the box where you type a question.

  • While it is open the tabs are narrower; when it is closed they have the full width. Where the page is narrow (a small window, the meeting list’s split panel at the side, a narrow embed) the panel lies over the right of the tabs instead of beside them. It stays in view while the page scrolls.
  • Open or closed is remembered for you in this browser, for every meeting, once you have opened or closed it. Until then it is open where the page is wide enough for it to sit beside the tabs, and closed where it would lie over them. A live meeting you have not opened before starts with the panel open; after that it is as you last left it.
  • The conversation is kept when you switch tabs or close and reopen the panel. Opening another meeting starts a conversation about that meeting.
  • What it offers: answers streamed as the Strands agent writes them, and chat shortcut buttons for common requests (Summary, Action Items, Topic and more), shown again after each answer.
  • Frames of the shared screen in an answer open full size when selected. Under the full-size frame, Show in transcript opens the Transcript tab at that moment and moves the player there, paused. Where the panel lies over the page, it closes to show the transcript.
  • Settings menu (administrators, in the Lambda assistant mode): Edit Chat Buttons, Open VP Live View / Close VP Live View, and MCP Servers.

The panel is shown only when the deployment has the meeting assistant enabled; otherwise there is no Assistant button. In the embeddable components, a call-details embed and a vp-details embed whose show includes chat start with the panel open; see Embeddable Components.

Screen share tab

Section titled “Screen share tab”

Shown for a meeting whose shared screen was captured, with the number of key frames in its label. A strip of thumbnails of the shared screen: one for each slide, page or view, with the time it went up and a short title, growing while the meeting runs. Frames that show only the meeting’s camera video are left out. Selecting one shows it large and moves the transcript and the player to that time; Show in transcript opens the Transcript tab there, and after the meeting Play recording from here opens it and plays the recording from there. Find text on the shared screen searches the slides’ text and Export slides (PDF) prints them as a deck. See Meeting Video and Key Frames.

Details tab

Section titled “Details tab”

  • Meeting attributes — the full Meeting ID, status, duration, the start and last-update times in UTC (with your local time under each), platform, owner, who the meeting is shared with, and, once the meeting has ended, its audio and video recordings: Play opens the Transcript tab and plays it in the player, and Open file opens the file in a new browser tab, to watch or save.

  • Capture and processing — how the meeting was captured and what happened to it, from the meeting record and what the page has loaded:

    • Captured with — Virtual Participant (with the platform, and a link to the Virtual Participant), Stream Audio, Browser extension, Desktop Capture App, Uploaded recording, or another client of the streaming API, as the meeting recorded it when it started.
    • Transcription engine — Amazon Transcribe or ASR MicroVM (a meeting that fell back from the MicroVM to Amazon Transcribe shows Amazon Transcribe), and Transcription language — the language code, Amazon Transcribe’s language identification, or, for the ASR MicroVM, the model’s own language.
    • Speaker separation — which channels it was asked for (both, the meeting audio, the microphone, or off), with how many voices the transcript tells apart.
    • Audio recording and Video recording — whether each was stored, or, for a Virtual Participant whose video recording was turned off, that it was.
    • Consent — the consent setting that applied (Off, Notify or Opt-in) and the status, with View the consent record.
    • Transcript retention — what the deployment’s Retention settings do to the transcript: kept for the days set to keep transcript segments, to be deleted at a given time, or deleted at a given time (with how many segments and files were removed) by Delete the transcript after the summary, so that a missing transcript is explained. When the meeting record says when it expires, that is given too.

    A meeting started before LMA recorded these shows no engine or language. Its source is inferred from the form of the Meeting ID each source writes (Stream Audio and the browser extension write the same form, so they are named together, and any other form is shown as not known), its speaker separation is read from the voice labels in the transcript, and the page says that both are inferred.

  • Speakers — name each voice once and the whole transcript updates; see Naming the voices.

  • Consent — for a meeting whose consent was in notify or opt-in mode: its mode and status, whether it may be recorded and transcribed now, the notice posted, each participant’s latest reply, the owner’s attestation, the evidence screenshots with a vision model’s check of each, and a timeline. The owner, anyone the meeting is shared with and an Admin can record an objection; the owner and Admins can check evidence; the owner can attest that everyone agreed, in an opt-in meeting whose rule is that the owner attests. The summary download includes the record. See Meeting Consent.

  • Estimated cost — the itemised estimate the header’s cost chip opens: Transcribe seconds, Bedrock tokens per feature, Nova Sonic, and the Virtual Participant’s compute, priced at dated list prices. It is labelled as an estimate and lists the lines it could not price and what it leaves out. See Meeting Cost Estimate.

Transcript Downloads

Section titled “Transcript Downloads”

Export meeting transcripts in multiple formats, from Download in the meeting page’s header once the meeting has ended:

  • Markdown (.md) — a paragraph per segment, **Speaker** [time]: text, under the meeting’s name, ID, date and duration
  • Word (.docx) — Word document format
  • Plain text (.txt) — Plain text format
  • Excel (.xlsx) — Spreadsheet format with structured columns
  • Copy to clipboard (Markdown) — the Markdown document, copied

The summary is offered in the same formats (Excel aside): Markdown and Word keep its sections as headings, with each picture of the shared screen written as its caption, and the consent record at the end when the meeting has one.

All export formats include speaker attribution and timestamps for each segment, and every channel the meeting has. A meeting chat message is under its sender marked as chat, Alice (chat), on one line: its line breaks become /. In the spreadsheet every value is stored as text exactly as typed, so a message that starts with =, +, - or @ is shown as written and is never treated as a formula.

Meeting Sharing

Section titled “Meeting Sharing”

Share meetings with other LMA users:

  1. Select one or more meetings from the meeting list
  2. Click the share icon
  3. Enter recipient email addresses
  4. Click Submit

On a meeting’s own page, Share in its header opens the same dialog for that meeting.

Only meeting owners can share meetings. Recipients receive read-only access to the shared meetings. For full details, see User-Based Access Control.

Meeting Deletion

Section titled “Meeting Deletion”

Delete meetings you own:

  1. Select one or more owned meetings from the meeting list
  2. Click the delete icon
  3. Type “confirm” in the confirmation dialog
  4. Click Delete

On a meeting’s own page, Delete meeting is in the ⋮ menu of its header.

Shared users automatically lose access to deleted meetings. For full details, see User-Based Access Control.

Admin Configuration Pages

Section titled “Admin Configuration Pages”

The following configuration pages are available to admin users only.

The Configuration page and the Edit Chat Buttons dialog edit settings that apply to every meeting in the deployment, so saving a change requires membership of the Admin Cognito group. That is enforced by the API, not just by the menu: the AppSync field pins the operation to the group and the resolver behind it checks the caller’s group membership again, so the two are independent. Add someone to the group on User Management if they need to change these settings. A user outside the group who opens the Configuration page sees a short message in place of the form; the Chat Buttons dialog is reached from a menu that only an Admin is shown.

All of these settings, and the meeting cost prices, are saved into one configuration profile, which records who saved it — the saver’s email address, or their Cognito username where the token carries none — and when, taken from the signed-in identity rather than from the request. A save is refused if someone else saved after the page was loaded, rather than replacing their change, and every save is recorded as a revision on the Configuration History page. See the Configuration Guide.

The other two pages in this section work differently and none of the above applies to them: MCP Servers manages one row per installed server, and User Management acts on the Cognito user pool directly.

Configuration

Section titled “Configuration”

Route: /#/configuration/settings

One page for every runtime setting, one section per part of the configuration, with the form for each generated from that section’s schema:

  • Values that differ from the shipped defaults are marked, with Reset to default beside each and Reset section to defaults for a whole section
  • Values are checked as you type, against the same rules a save is checked against
  • Save changes asks for an optional comment and label for the revision the save records, and saves every changed section together
  • A save refused because someone else saved first can be reloaded with your changes kept over theirs
  • ?section=<name> opens one section directly, for example /#/configuration/settings?section=call_pricing, which Configuration ▸ Meeting Cost Prices in the navigation opens: the table of unit prices each meeting’s estimated cost uses, with the source of each (see Meeting Cost Estimate)

See the Configuration Guide for full documentation.

Chat Buttons

Section titled “Chat Buttons”

Customize the chat shortcut buttons that appear in the meeting chat panel:

  • Open the Edit Chat Buttons modal from the settings menu of the meeting detail page’s assistant panel
  • Add new shortcut buttons with custom labels and prompts
  • Edit existing button labels and prompts
  • Delete buttons you no longer need
  • Reset to Defaults brings back the shipped buttons

Once any custom button is saved, the custom list replaces the shipped one entirely; it does not add to it. The buttons are stored in the shared configuration store, and a save is refused, with a message to reopen the dialog, if someone else saved the configuration while it was open.
